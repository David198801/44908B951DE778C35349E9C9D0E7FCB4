```javascript
SQLNET.ALLOWED_LOGON_VERSION_SERVER=11
SQLNET.ALLOWED_LOGON_VERSION_CLIENT=11
```

**不需重启数据库和监听，新的连接就可以正常连接了。**

**SQLNET.ALLOWED_LOGON_VERSION_SERVER：**控制可以连接到19c数据库的客户端版本（client —>oracle 19c db ）

**SQLNET.ALLOWED_LOGON_VERSION_CLIENT:**控制19c数据库可以连到哪些版本的数据库（oracle 19c db —>其它版本的oracle db），例如：控制通过DB LINK可连接到哪些版本的oracle库。

该参数用来限制可以连接到[数据库服务](https://cloud.tencent.com/product/tencentdb-catalog?from_column=20065&from=20065)器上的最小客户端版本，比如设置值为10，即10g，11g等以上客户端版本可以连接到数据库服务器上，在不是指的时候是用默认值的，导致低版本连接不上高版本的数据库。

这里说的 8,10,11 版本指的是 **dba_users.password_versions** 的版本。
# 然后必须修改一次密码！！
## 从 `ORA-28040`（协议不匹配）变成 `ORA-01017`（用户名/密码错误），说明**连接协议通道已经打通，但数据库拒绝了凭证**。

在修改了 Oracle 的 `sqlnet.ora`（允许了旧版本连接）后，最容易遇到这个现象。原因和解决方法如下：

### 原因：Oracle 缺少兼容旧协议的“密码哈希值（Verifier）”

当你修改了数据库的 `SQLNET.ALLOWED_LOGON_VERSION_SERVER` 参数后，Oracle 允许了旧版本的客户端连接。但是，**数据库中现有用户的密码哈希值是在高版本安全策略下生成的，没有生成兼容旧版本的哈希值。**

因此，即使你的用户名和密码完全正确，Oracle 在比对旧协议传过来的密码时也会失败，从而报 `ORA-01017`。

---

### 解决方法

#### 在数据库端重置该用户的密码（必须）
你需要在 Oracle 数据库中，**重新对该用户执行一次修改密码的命令**（可以改成与原密码相同的密码）。这样 Oracle 才会用新的安全兼容级别重新生成密码哈希。

1. 用 DBA 账户（如 `sysdba`）登录 Oracle 数据库。
2. 执行以下命令重新设置密码：
   ```sql
   ALTER USER 你的用户名 IDENTIFIED BY 你的密码;
   ```
   *(例如：`ALTER USER acs IDENTIFIED BY mypassword123;`)*
3. 检查用户的密码版本：
   ```sql
   SELECT username, password_versions FROM dba_users WHERE username = '你的用户名';
   ```
   * 正常情况下，修改后 `PASSWORD_VERSIONS` 字段应该会显示类似 `10G 11G 12C`（表示兼容多种版本的客户端验证）。
