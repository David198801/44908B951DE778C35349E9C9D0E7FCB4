在 Windows 系统上，`uv` 的默认缓存路径是 `%LOCALAPPDATA%\uv\cache`。这个路径通常展开为 `C:\Users\<你的用户名>\AppData\Local\uv\cache`。

### 💡 如何通过环境变量指定缓存路径

你可以通过设置环境变量 `UV_CACHE_DIR` 来永久修改缓存路径。这里有几种设置方法：

*   **通过图形界面设置（推荐）**：
    1.  在Windows搜索框输入“环境变量”，并打开“编辑系统环境变量”。
    2.  在“高级”选项卡下，点击“环境变量”。
    3.  在“用户变量”或“系统变量”区域，点击“新建”。
    4.  变量名填写 `UV_CACHE_DIR`，变量值填写你想要的完整路径（例如 `D:\uv\cache`）。
    5.  一路点击“确定”保存，并**重启**你的终端窗口使设置生效。

*   **通过命令行设置（临时生效）**：
    在当前的命令提示符 (CMD) 窗口中运行以下命令，关闭窗口后即失效。
    ```cmd
    set UV_CACHE_DIR=D:\uv\cache
    ```

*   **通过命令行设置（永久生效）**：
    使用 `setx` 命令可以将环境变量永久添加到用户环境变量中。
    ```cmd
    setx UV_CACHE_DIR "D:\uv\cache"
    ```

### 🚀 其他实用命令

*   **查看当前缓存路径**：在终端中运行 `uv cache dir` 可以随时查看当前生效的缓存目录。
*   **单次命令指定**：执行安装命令时，也可以通过 `--cache-dir` 参数临时指定缓存路径。
    ```cmd
    uv pip install <package_name> --cache-dir D:\uv\cache
    ```

### ⚠️ 注意事项

*   **路径问题**：设置的路径必须是一个**已存在的目录**，否则 `uv` 可能会报错。
*   **性能优化**：将 `UV_CACHE_DIR` 设置到与你的 Python 项目**同一个磁盘分区**（例如都在D盘），可以让 `uv` 利用硬链接（Hard Link）技术，实现不同虚拟环境间共享同一份包文件，从而**极大节省磁盘空间并提升安装速度**。

简单来说，在 Windows 上管理 `uv` 缓存就是三步：找到默认路径（`%LOCALAPPDATA%\uv\cache`），通过设置 `UV_CACHE_DIR` 环境变量来修改它，然后用 `uv cache dir` 命令来验证。





# 清理缓存

清理 `uv` 缓存主要有三种方法，从最彻底到最精细，你可以按需选择。

### 🧹 方法一：彻底清理 (uv cache clean)

这个命令会**删除整个缓存目录**，是最直接、最彻底的清理方式。

```bash
uv cache clean
```
*   **清理特定包**：如果只想清理某个特定包的缓存，可以指定包名。
    ```bash
    uv cache clean ruff
    ```

### ✂️ 方法二：智能修剪 (uv cache prune)

这个命令更“温柔”，它会**安全地移除所有不再需要的、过时的缓存条目**，例如来自旧版 `uv` 的残留文件。这是一个既能释放空间，又能保留有用缓存的好方法。

```bash
uv cache prune
```
*   **CI环境优化**：还有一个专门为持续集成（CI）环境设计的参数，可以更积极地清理缓存。
    ```bash
    uv cache prune --ci
    ```

### 🗑️ 方法三：手动删除

如果因为某些原因（如进程占用）导致命令行操作失败，你可以直接手动删除缓存文件夹。

1.  打开文件资源管理器。
2.  在地址栏输入 `%LOCALAPPDATA%\uv\cache` 并回车。
3.  删除该文件夹下的所有内容。

> **注意**：手动删除前，请确保没有 `uv` 相关的进程正在运行，否则可能因文件被占用而删除失败。

### 💡 其他实用技巧

*   **查看缓存位置**：不确定缓存目录在哪？可以用这个命令查看。
    ```bash
    uv cache dir
    ```
*   **刷新缓存而非删除**：如果不想删除，只是想强制 `uv` 重新验证和下载依赖，可以在安装或同步命令后加上 `--refresh` 参数。
    ```bash
    uv sync --refresh
    ```
*   **谨慎操作**：`uv cache clean` 命令会**直接删除**整个缓存目录，操作前请务必确认 `UV_CACHE_DIR` 环境变量指向的是正确的缓存路径，避免误删重要文件。

建议优先使用 `uv cache prune` 进行常规清理，既安全又能有效释放空间。如果发现缓存目录过大，再考虑使用 `uv cache clean` 进行彻底清理。

`uv` 的缓存目录内部结构是按功能划分的，主要包含几个不同的“桶”（buckets）。

### 🗂️ 缓存目录结构

当你打开缓存目录（例如 `%LOCALAPPDATA%\uv\cache`）时，会看到如下结构：

*   **`buckets/`**：这是核心目录，包含了主要的缓存数据。
    *   **`wheels-v*`**：存储已下载的 Wheel 格式的包文件。
    *   **`sdists-v*`**：存储源代码分发包（Source Distributions）。
    *   **`git-v*`**：存储从 Git 仓库克隆的包。
    *   **`simple-v*`**：存储从 PyPI 等包索引获取的元数据响应。
    *   **`core-metadata-v*`**：存储解析包依赖时使用的核心元数据。
*   **`CACHEDIR.TAG`**：一个标识文件，用于告诉系统这个目录是缓存，避免被意外备份或索引。
*   **其他文件**：可能还包含一些锁文件或其他临时元数据。

### 💡 关键点

*   **“桶”和版本控制**：每个“桶”的名称都带有版本号（如 `v12`、`v13`）。`uv` 通过版本号来管理缓存格式的兼容性，避免因版本更新而读取错误数据。
*   **设计为“只追加”**：`uv` 的缓存是“只追加”（append-only）的，这意味着它只会不断写入新数据，而不会修改已存在的缓存文件。这也是为什么清理缓存时，直接删除整个目录是安全的。

### 🗑️ 手动删除时的注意事项

由于缓存是“只追加”的，直接删除整个 `cache` 文件夹是完全安全的。

*   `uv` 在下次运行时，如果发现缓存缺失，会自动重建所需的目录结构和文件。
*   删除缓存不会影响已创建好的虚拟环境（`.venv` 文件夹）或项目配置文件。
*   为了获得最佳性能，建议将缓存目录与你的 Python 虚拟环境放在**同一个文件系统（即同一个磁盘分区）**上。
*   如果你因权限或文件占用问题无法删除，可以尝试先关闭所有终端和 IDE，或者重启电脑后再操作。
